Protecting sensitive health information with a client-owned security boundary

ZK Fitness is a full-stack fitness platform built around a clear privacy boundary. The browser owns readable workout records, private keys, and analytics. Workout history can reveal sensitive health and lifestyle information, so the optional API receives public key material and opaque encrypted payloads instead of readable records.

What is implemented

  • Strength, cardio, and time-based sessions with reusable plans
  • Exercise search, custom exercises, history, charts, records, XP, badges, and streaks
  • Local mode without an account, backed by encrypted IndexedDB records
  • Optional account mode, encrypted sync, Groth16 proof verification, PostgreSQL persistence, and Docker startup
  • Argon2id and HKDF key derivation, AES-256-GCM payload encryption, ML-DSA-65 login signatures, ML-KEM-768 key encapsulation, Poseidon commitments, and a Circom Groth16 workout-validity circuit

How I approached it

The server is responsible for sessions, validation, rate limits, health checks, proof verification, replay checks, and storage. It does not receive the password, private keys, or readable workout records. The client decrypts the record before calculating analytics. The proof verifies a declared sensitive workout summary and its binding to the encrypted record metadata. It does not prove the AES-GCM or ML-KEM internals or that the ciphertext decrypts to that summary.

Post-quantum algorithms are included as an engineering exploration. A fitness app does not commercially require them by default. They make the project a useful place to study larger keys, challenge-response authentication, key encapsulation, and browser performance tradeoffs.

Scope

This repository includes automated unit, backend integration, browser flow, ZK artifact self-test, lint, Docker build, dependency audit, secret-pattern, and guardrail checks. The browser suite focuses on local trial workflows. It does not prove coverage across every browser and failure mode, an independent security assessment, or operational reliability.
